# Task

模板只提供一个 10 ms 静态 FreeRTOS 控制任务骨架，用于验证调度器、移植层和全局
看门狗调用链，不包含具体产品 Task 或 Device/Mode 编排。
任务名称、周期、栈深度和优先级偏移集中定义在
[`config/core_config.h`](../config/core_config.h) 的“Task 与调度”分区。

`task_app.c` 是全局 250 ms WWDT1 的唯一运行期喂狗者，只在当前
10 ms 控制周期完整返回且 APP 健康策略满足后喂狗。禁止把喂狗移入 Tick/Idle/ISR，
也禁止其他 Task 独立喂狗；新增关键 Task 时按
[`docs/WATCHDOG.md`](../docs/WATCHDOG.md) 汇总当前周期健康状态。

`g3519-bringup-debug/release` 额外编译静态 `Task_BringupChassis`：周期和 deadline
均为 10 ms、优先级 `tskIDLE_PRIORITY+1`、栈深 512 个 `StackType_t`。停车时长按
PB31 KEY 在赛题第2～6项之间循环选择，短按确认当前项；第2项使用末段终点横杠
修正停车目标，未识别横杠时以左右编码器平均里程的一圈 `6141.6 mm` 目标兜底。
第2项全程由亚博灰度循迹输出控制左右轮差速，不叠加INS路线前视或ICM绝对航向PID；
ICM仍采集供显示和VOFA观察，但不再作为第2项发车门槛。第2项先按左右编码器平均里程
一圈`6141.6 mm`初始化漏检兜底目标；灰度失鲜或丢线超过既有250 ms缓冲后请求规划停车。
第2项循迹目标使用单侧 `230 mm/s`（左右差`460 mm/s`）上限；左右轮仍各自保留
`±600 mm/s` 最终限幅；
第4项当前作为隔离测试，以发车时 ICM yaw 为目标，由角度 PID 在纵向规划速度两侧生成
小幅差速，沿 AB 直行并以 1500 mm 为目标线性停车，不叠加灰度或路径前视转向；第5/6项
通过 A 后保留一车长停车距离，第3项保持底盘
锁定用于静车滚球。运行中短按仍请求线性规划停车，
长按不会切换赛题。停车待机期间持续检查发车硬件；只有灰度样本新鲜且检测到线、
ICM45686 当前反馈有效且陀螺零偏标定完成、PeerLink 在线，并且现有 Bring-up 故障为零时，
短按确认才允许发车。JY61P 仍只作标定和指示，不进入发车门槛。
初始化 1 s 后 UART3 只发送一次 `$0,1,0#`，随后每 10 ms 排空模块主动上报的
`$A,x1:...,...,x8:...#`；每个新帧无论停车还是运行都只把原始八路 ADC 送入既有共同
基线消除和模拟位置估计，不采用厂家示例灰度算法。纵向前进目标由左右编码器平均里程驱动的线性
速度规划器生成；航向只由完成零偏标定的 ICM45686 陀螺仪传播，编码器差分不再校正航向，
陀螺无效时也不回退到编码器航向。H 题默认直道 420 mm/s、半圆 300 mm/s，且在 B/D 前按制动包络提前换速。
第2项的 D→A 半圆前段仍采用 300 mm/s 圆弧速度上限，但会在终点横杠搜索窗下沿前
线性降至 220 mm/s；降速只改变纵向均速，完整灰度循迹差速与既有半差限幅保持生效。
其他终点横杠模式在预计横杠窗口前降至 100 mm/s。横杠确认后，各模式按自身
标记后距离更新停车目标；现有规划器仍按
185 mm/s²线性减速，因此物理停车距离不会为零。有效灰度帧
只由 `Mode_Car_AnalogTracking` 生成横向差速修正，任务2使用其完整输出，
现有双轮速度控制器继续作为
10 ms 内环。通道从左到右
权重为 `-0.70,-0.45,-0.20,0,0,0.20,0.45,0.70`，该产品 Task 单独使用循迹
`Kp=0.70`；运动项在短时丢线（250 ms内）保留当前规划，超时后请求规划停车。当前
前视距离为 200 mm；第2项的路线前视允许跨过 A 继续 200 mm，防止一圈终点把前视点
固定在车后；第4项隔离测试不消费该转向输出，第5/6项对准通过A后320 mm。
超过辅助窗口后由
里程速度规划器前瞻减速到零，不从巡航速度直接清零。正常里程目标和运行中短按均先
稳定零速，再锁定两个底盘电机 Device；停车事件不再跨板发送。

终点横杠不改变原模拟循迹算法。最新VOFA在约`5726～5755 mm`出现唯一的八路共同抬高
脉冲，因此产品Task只在`5800±300 mm`末段窗口检测；必须先收到一个普通线帧，之后
同时满足至少6/8路ADC不低于900、八路平均值不低于1700且连续两个新帧，才锁存一次
横杠里程。同一帧不会重复累计，窗口外不累计。第2项确认横杠后继续纯灰度循迹，并把
停车目标改为横杠里程加源码顶部宏定义的`180 mm`；若未确认横杠，左右编码器平均里程
一圈`6141.6 mm`仍作为漏检兜底。
第5/6项在该通过 A 的
基准点后再加全车长度 320 mm，停车目标为横杠里程+320 mm。一圈+320 mm继续作为
通过 A 模式的漏检兜底。减速度为 185 mm/s²，横杠
确认后仍由同一速度规划器线性减速，不直接清零电机。任务2在窗口下沿前达到220 mm/s，
其左右轮仍叠加完整灰度差速。900、1700平均值、6/8、
`5800±300 mm`窗口和180 mm后续距离均
为当前产品参数，须继续用横杠处 x1～x8 与最终停车位置实测校准。CH7 会反映横杠锁存后
更新的剩余距离，CH14～CH21 可直接观察横杠处八路原始 ADC。

题面几何已按图1核对：A左上、B右上、C右下、D左下，路线固定为
`A→B→C→D→A`顺时针，AB/CD各1500 mm，BC/DA各为R500半圆，一圈6141.6 mm。
几何公式正确不等于停车已经达到题面`≤2 cm`：评分按车体中心轴线上唯一测试点到A停车
基准线的距离，而不是灰度探头位置。当前`5800±300 mm`窗口和横杠后`180 mm`附加距离
仍需同次实测“探头触线、车体测试点过线、最终停点”后分别标定；源码与编译不能替代该实物闭环。

蓝牙每 20 ms 最多提交一行固定 32 列 FireWater 调试遥测：CH0 为本次发车路程
mm；CH1/CH2 为左右实测轮速 mm/s；CH3/CH4 为左右目标轮速，第4项包含发车 yaw
角度 PID 修正，其他运动项包含 INS 与灰度修正；CH5/CH6 为速度规划器的参考速度 mm/s 和参考加速度 mm/s²；CH7/CH8 为目标
剩余距离和当前制动触发距离 mm；CH9 为 yaw；CH10 为归一化灰度线误差（右偏为正，
样本过期为 0）；CH11 为速度阶段（0 空闲、1 加速、2 巡航、3 制动、4 停止）；CH12
为绝对摆杆 Pitch，即 `ICM45686 车体 Pitch + JY61P 摆杆相对 Pitch`；CH13
为最近一帧校验正确的 JY61P `0x53` 欧拉角样本年龄 ms；CH14～CH21 依次为亚博
`x1..x8` 原始 `uint16_t` ADC，未收到合法样本或样本超过 100 ms 时八路均输出0。
CH22～CH31依次为F407处理后底盘加速度`mm/s²`、ICM补偿角`mdeg`、最终杆目标`mdeg`、
QD4310目标/反馈raw、命令/反馈电流`mA`、速度`0.01 rpm`、控制phase和状态flags。
G3519收到的DBG年龄不超过100 ms时在CH31额外置bit9；101 ms起CH22～CH31全0，便于VOFA
明确区分有效全零状态和链路超时。CH31 bit0～bit8仍原样来自F407。
任一 Pitch 无效或 JY61P 样本超过 500 ms 时，CH12 输出0、CH13 输出9999，不得把该点
写入电机角度标定表。维特
使用当前空闲的 UART0 PB0/PB1、115200 8N1，只服务摆杆/QD4310 标定和指示，不进入
车体惯导、速度规划、PeerLink、F407 或任一电机控制环。安装时应使维特 Y 轴平行右侧
转轴 O、X 轴沿摆杆，传感器中心距 O 约 10～30 mm；JY61P Pitch 项须先按杆面水平
零位完成安装零偏标定，再与车体 ICM45686 Pitch 相加。当前源码不会对 Pitch 自动
Tare；`Device_JY61P` 的自动/显式 Tare 只作用于 yaw，杆面水平零偏必须在模块或安装
标定侧明确完成。同步语义是 ICM 更新、JY61P 串口消费和 20 ms 遥测共用同一 10 ms
Task 心跳时间戳；不做跨板传输，也不宣称两颗传感器具有硬件触发的同时采样。
20 ms VOFA 周期和 115200 8N1 非阻塞蓝牙发送不变。G3519板间活动发送只保留
`HB/CAR`，另接收F407的50 Hz只读`DBG`并转发到VOFA；JY61P、灰度和里程不跨板，
DBG也不进入任何车端或滚球控制。当前 WCET、最大调度抖动和栈高水位尚未上板测量；
该 Task 不参与全局喂狗决策。

Bring-up Task 同时持有一个 `Device_PeerLink`：UART1 PB4/PB5 使用 DMA_CH1/CH0，
作为节点 2 每 500 ms 与 F407 节点 1 双向交换心跳，以 100 Hz 发送七字段 `CAR`
实测状态。两种 Packet 各用独立序号；发送队列 BUSY 时整帧丢弃且不推进对应序号，
无 ACK 或自动重试。F407 用本地接收时刻判断
新鲜度，不拿两块 MCU 的毫秒时钟直接相减。1500 ms 未收到合法心跳时 PeerLink 离线。

`CAR` 包含平均实测车速、ICM45686 车体 X/Z 轴加速度计比力、零偏校正后的
Y/Pitch 角速度、采样时刻和有效位。比力没有去重力，静止水平时 Z 轴理论上约为
`+9807 mm/s²`。编码器、IMU、陀螺零偏或启动校准任一无效时，四个物理量全部发送0且
`valid=0`。F407 当前只保存该帧供观察，前馈增益保持0。
链路由同一 10 ms 周期非阻塞推进，故障只记录在 `g_peer_link_fault`，不停止底盘
Device。完整协议以 F407 工程的 `MCU_UART_HEARTBEAT_PROTOCOL.md` 为准。

删除 `TEL/ENC` 后 G3519 不再知道 QD4310 是否在线，不能再用 QD 状态阻止底盘发车；
QD4310 掉线、反馈过期和 Disable 保护归 F407 本地。G3519 发车门仍要求 F407 的
PeerLink 心跳在线，不能把这个 MCU 在线位描述成 QD4310 在线位。

Bring-up 启动后还会在自身低优先级 Task 中初始化一次 G3519 的 ST7735S，并将
128×160 全屏填充为红色作为最小显示自检。初始化与填充为约 460 ms 的有界阻塞启动
操作，随后用约 25 ms 将未使用区域一次清黑；两者均发生在调度器启动后，更高优先级的
10 ms `Task_Control` 仍可抢占并喂 WWDT1。之后进入 4 行状态页：灰度只显示 `LINE:OK`、
`LINE:LOST` 或 `LINE:STALE`；车辆行显示发车/停车及本次巡检时间；通信汇总行显示
`COM:I1 L1`，其中 `I` 是 ICM45686 当前有效位、`L` 是 PeerLink 在线位，两者都在线
为绿色，任一无效或离线为红色；模式行显示 `M2:LAP STOP`、`M3:STATIC BALL`、
`M4:A-B YAW HOLD`、`M5:LAP CENTER` 或 `M6:LAP TARGET`，黄色表示待短按确认，绿色表示
已确认。原
ID/使能、电流、转速、角度、绝对编码器、心跳和
故障明细不再显示。界面使用 Task 私有 5×7 字模和 4 KiB 静态行缓冲，每 50 ms 最多
检查一行，约 200 ms 检查一轮页面；文字和颜色未变化时不发送 SPI，普通数字变化只重绘
发生变化的 8×16 字符格，首次显示或颜色变化才重绘整条 128×16 行。显示失败只写
`g_BRINGUP_DisplayFault`（1 默认配置、2 初始化、3 尺寸、4 启动填充/清屏、5 状态行更新），
不改变 `g_BRINGUP_Fault`，也不停止底盘、蓝牙或 PeerLink。

巡检时间从短按确认成功发车时清零，运行中按同一无符号毫秒时钟累计。第2项在一圈里程
规划停稳后取最终时间；第4项通过 B 的 1500 mm 时锁定成绩时间；第5/6项在车体基准通过 A
时锁定成绩时间，之后一车长停车过程不计入显示成绩。发车成功后 TFT 完全停止状态检查、
文字格式化和 SPI 更新；车辆
稳定停车或故障停车时立即只刷新 `CAR:STOP mm:ss.d` 最终时间，随后恢复每 50 ms 一行的
待机扫描。运行期间屏幕保留发车前的最后画面，不绘制递增的 `CAR:RUN` 时间。受 16 字符
宽度限制，最终时间显示上限为 `99:59.9`；该显示计时不进入速度规划、VOFA 或板间协议。
