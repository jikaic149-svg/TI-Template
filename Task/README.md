# Task

模板只提供一个 10 ms 静态 FreeRTOS 控制任务骨架，用于验证调度器、移植层和全局
看门狗调用链，不包含具体产品 Task 或 Device/Mode 编排。
任务名称、周期、栈深度和优先级偏移集中定义在
[`config/core_config.h`](../config/core_config.h) 的“Task 与调度”分区。

`task_app.c` 是全局 250 ms WWDT1 的唯一运行期喂狗者，只在当前
10 ms 控制周期完整返回且 APP 健康策略满足后喂狗。禁止把喂狗移入 Tick/Idle/ISR，
也禁止其他 Task 独立喂狗；新增关键 Task 时按
[`docs/WATCHDOG.md`](../docs/WATCHDOG.md) 汇总当前周期健康状态。

`g3519-bringup-debug/release` 额外编译静态 `Task_BringupChassis`：周期和 deadline
均为 10 ms、优先级 `tskIDLE_PRIORITY+1`、栈深 512 个 `StackType_t`。停车时长按
PB31 KEY 在赛题第2～6项之间循环选择，短按确认当前项；第2项使用末段终点横杠
修正停车目标，未识别横杠时以左右编码器平均里程的一圈 `6141.6 mm` 目标兜底。
第2项在终点横杠前由亚博灰度循迹输出控制左右轮差速，不叠加INS路线前视或ICM绝对航向PID；
ICM仍采集供显示和VOFA观察，但不再作为第2项发车门槛。第2项先按左右编码器平均里程
一圈`6141.6 mm`初始化漏检兜底目标；灰度失鲜或丢线超过既有250 ms缓冲后请求规划停车。
第2项循迹目标使用单侧 `230 mm/s`（左右差`460 mm/s`）上限；左右轮仍各自保留
`±600 mm/s` 最终限幅；

规划；M3保持底盘锁定。第4项以发车时 ICM yaw 为目标，由角度 PID 在纵向规划

题面几何已按图1核对：A左上、B右上、C右下、D左下，路线固定为
`A→B→C→D→A`顺时针，AB/CD各1500 mm，BC/DA各为R500半圆，一圈6141.6 mm。

蓝牙每 20 ms 最多提交一行固定 32 列 FireWater 调试遥测：CH0 为本次发车路程
mm；CH1/CH2 为左右实测轮速 mm/s；CH3/CH4 为左右目标轮速，第4项以及第2/5/6项标记后的
制动段包含发车 yaw 角度 PID 修正，其他运动项包含 INS 与灰度修正；CH5/CH6 为速度规划器的参考速度 mm/s 和参考加速度 mm/s²；CH7/CH8 为目标
剩余距离和当前制动触发距离 mm；CH9 为 yaw；CH10 为归一化灰度线误差（右偏为正，
样本过期为 0）；CH11 为速度阶段（0 空闲、1 加速、2 巡航、3 制动、4 停止）；CH12
为左右轮平均速度差分并经80 ms一阶低通得到的实测纵向加速度 mm/s²，保留两位小数；
CH13为闭环相对“相同限跃度、反馈增益为0”的开环参考加速度实际修正量 mm/s²，也保留
两位小数，负值表示闭环压低参考加速度。加速度误差可直接用CH6减CH12得到；CH14～CH21依次为亚博
`x1..x8` 原始 `uint16_t` ADC，未收到合法样本或样本超过 100 ms 时八路均输出0。
CH22～CH31依次为F407处理后底盘加速度`mm/s²`、ICM补偿角`mdeg`、最终杆目标`mdeg`、
QD4310目标/反馈raw、命令/反馈电流`mA`、速度`0.01 rpm`、控制phase和状态flags。
G3519收到的DBG年龄不超过100 ms时在CH31额外置bit9；101 ms起CH22～CH31全0，便于VOFA
明确区分有效全零状态和链路超时。CH31 bit0～bit8仍原样来自F407。
固定32列VOFA不再复用CH12/CH13传输JY61P角度；杆角标定仍使用独立静态缓存，且在
JY61P初始化停用期间不会取得有效欧拉角。维特预留使用当前空闲的 UART0 PB0/PB1、115200 8N1，只服务摆杆/QD4310 标定和指示，不进入
车体惯导、速度规划、PeerLink、F407 或任一电机控制环。安装时应使维特 Y 轴平行右侧
转轴 O、X 轴沿摆杆，传感器中心距 O 约 10～30 mm；JY61P Pitch 项须先按杆面水平
零位完成安装零偏标定，再与车体 ICM45686 Pitch 相加。当前源码不会对 Pitch 自动
Tare；`Device_JY61P` 的自动/显式 Tare 只作用于 yaw，杆面水平零偏必须在模块或安装
标定侧明确完成。当前Task不初始化或消费JY61P串口；若后续重新启用，仍不得宣称它与
ICM45686具有硬件触发的同时采样。
20 ms VOFA 周期和 115200 8N1 非阻塞蓝牙发送不变。G3519板间周期发送保留
`HB/CAR`，另按请求发送`BTG/BST`并接收F407的50 Hz只读`DBG`转发到VOFA；JY61P、灰度和里程不跨板，
DBG也不进入任何车端或滚球控制。当前 WCET、最大调度抖动和栈高水位尚未上板测量；
该 Task 不参与全局喂狗决策。

MCP通过单个32位原子邮箱`g_BRINGUP_BallCommandMailbox`提交滚球命令：高16位是每次
必须更新且非零的请求号，低16位按`int16_t`解释；`-1200..1200`表示0.1 mm目标，
`INT16_MIN`表示BST。Task不清邮箱，只处理新的完整32位值。状态依次可为IDLE、WAIT_LINK、
BUSY_RETRY、QUEUED、INVALID、BUSY_EXHAUSTED或SEND_ERROR；
`g_BRINGUP_BallCommandLastQueued`只确认本地UART入队。每周期最多尝试一次，连续3次BUSY
即停止，使用新请求号才重提。M3按键选择/确认语义不变，BTG不隐式启动F407滚球闭环。

Bring-up Task 同时持有一个 `Device_PeerLink`：UART1 PB4/PB5 使用 DMA_CH1/CH0，
作为节点 2 每 500 ms 与 F407 节点 1 双向交换心跳，以 100 Hz 发送九/十一/十三字段 `CAR`
状态，尾部同步当前赛题号`2..6`和任务活动位。M4/M5/M6运行期间发送同一轮速规划器的
规划加速度及独立有效位；M2/M3保持九字段。M3短按KEY只切换任务活动位，不再提交
BTG/BST，也不控制F407的QD4310/CAN使能状态。mode只供F407和视觉侧显示/诊断，不触发滚球
启停或改变目标。两种 Packet 各用独立序号；发送队列 BUSY 时整帧丢弃且不推进对应序号，
无 ACK 或自动重试。F407 用本地接收时刻判断
新鲜度，不拿两块 MCU 的毫秒时钟直接相减。1500 ms 未收到合法心跳时 PeerLink 离线。

`CAR` 包含平均实测车速、ICM45686 车体 X/Z 轴加速度计比力、零偏校正后的
Y/Pitch 角速度、采样时刻和有效位。比力没有去重力，静止水平时 Z 轴理论上约为

终端jerk退出后立即恢复九字段CAR，由F407本地BMI088接管残余停车冲击；发车前和运行
结束后也保持九字段。
链路由同一 10 ms 周期非阻塞推进，故障只记录在 `g_peer_link_fault`，不停止底盘
Device。完整协议以 F407 工程的 `MCU_UART_HEARTBEAT_PROTOCOL.md` 为准。

## Filtered wheel acceleration diagnostics (2026-08-01)

M4/M5/M6 run a separate mean-wheel acceleration estimator for F407 fusion.
It uses a 13-sample least-squares speed slope, a 100 ms low-pass, and a
`+/-1000 mm/s2` clamp. It does not replace the speed profile's existing CH12
measurement or acceleration feedback. VOFA appends CH32=filtered wheel
acceleration (`mm/s2`) and CH33=explicit validity. When the plan is inactive,
the estimator resets and both channels are zero.
